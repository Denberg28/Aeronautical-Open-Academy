# Aeronautical Open Academy 0.5.0-alpha.1 — development test build

The learning app now acts as a link to knowledge hosted on Google and other platforms. Instructors paste plain text plus HTTP/HTTPS addresses directly into subject descriptions or a single material entry. The first line becomes the material title. Saved addresses become compact underlined hyperlinks such as Google Docs, Google Slides, Google Sheets, Google Drive, YouTube, PDF/spreadsheet host labels, or the website hostname, followed by an external arrow. HTTP links are identified as HTTP. No separate URL/type form or per-link Open button is needed.

Students tap a hyperlink; the app rechecks active session, enrollment, published content and the exact current reference, then opens the browser or host application. Originals remain on their platforms. Host sharing permissions, Google/other sign-in, availability, redirects, downloads and external offline features stay with the host. No app token is passed to it. The app does not fetch, embed, preview or proxy linked content, and does not change sharing permissions. Reading remains a separate student-reported action; opening a link is not proof of reading or achievement.

New MATERIAL_STORAGE=links mode needs no Drive service account or file store. A backend is still required for accounts, eligibility, references, quizzes, outputs and results. Existing private file adapters remain optional; keep the original Drive/local-development configuration to serve prior uploaded PDFs. With file storage disabled, unavailable legacy PDF actions show guidance instead. Public sample A/B/C downloads remain independent.

Public HTTP/HTTPS references are supported; unsafe schemes, embedded credentials, literal IP/local addresses and custom ports do not become clickable links. Reference endpoints reject injected URLs, stale text/revisions, drafts and revoked access. Links already copied or opened remain subject to host access controls; the Academy cannot recall them or track provider-side edits.

Upgrade both Android and server to 0.5. Back up the stopped backend first. Additive SQLite v4 records text versus legacy file materials while preserving IDs, eligibility, enrollment sources, files, progress and results. Existing materials retain file mode. Old servers refuse v4; rollback requires restoring the complete pre-upgrade backup with its matching server. Prefer a forward app fix with retained signing identity; uninstall clears local data.

Android 8.0/API 26+, SDK 35, JDK 17; Node 24.19.0 backend. This .test APK uses a development key, potentially different between CI runs; install may require uninstalling the previous test app. It is a development test release. Backend hosting, real browser/provider permissions, Android/TalkBack/lifecycle/device validation and retained production signing remain unconfigured or unverified. No default credentials, real learner data or private organization links are included.
